# AGENTS.md — SIREN

**SIREN** — Satellite-Informed Risk & Emergency Network. Satellite-assisted early warning and disaster-response decision platform for Himalayan glacial lake outburst flood (GLOF) events.

> **Origin:** Originally built at the >.hack();'26 36-hour hackathon (Track 7: resilient alerting + disease prevention). Now an ongoing personal research project pursuing an end-to-end differentiable neural pipeline from raw radar bytes to downstream flood dynamics.

**Read before writing code:** `docs/spec/PRD.md` (v5.1 — DL-primary declaration, data contracts, scoring formulas, end-to-end neural pipeline §9.7, promotion pathway §9.8) and `docs/spec/BUILD_ROADMAP.md` (phase history + active development roadmap). This file tells you *how to work*; those tell you *what to build*.

> **Build status (PRD v5.1, 2026-09-17):** **DL-primary is the declared target architecture** — trained segmentation, neural bathymetry, latent-conditioned FNO, and learned risk fusion form the intended analytical spine. The deterministic/empirical baseline (Huggel + calibrated 2-channel FNO + NDWI/backscatter) is currently the load-bearing *interim* path and permanently remains the labeled fallback/cross-check/regression harness; each neural component is promoted component-wise via the §9.8/§17.2 gates on held-out real data — **promoted `sar_segmentation_expansion` (Δp mask) → OPERATIONAL-PRIMARY within certified scope (descending orbit, monsoon Jun–Sep, Imja vicinity): the gated Δp expansion inside monitorable-lake vicinity drives `water_area_change_percent` in the hazard score; registry value kept as labeled cross-check; `SIREN_ML_DEMOTE` env var reverses at runtime. Advisory-primary: `susceptibility` (spatial model, isotonic-calibrated, conformal q=0.82), `dynamic_escalation` (Tier-2 weather/morphology XGBoost, AUC 0.838 / Brier 0.143)** — all recorded in `ml/promotion.py::PROMOTED_COMPONENTS` with scope, union policy, and caveats; promoted outputs surface as reasons on the review card while the human gate stays authoritative. The runtime prefers the verified **descending pair (2026-07-02 + 2026-07-14) that covers Imja Lake** (`find_imja_descending_pair` in `preprocess/sar_calibrate.py`), with per-observation fallback; SAR-pair + model provenance persists to `change_stats` and `/runs/{run_id}/ml-evidence`. > **E2 neural bathymetry — LOO benchmark evaluated (2026-09-15):** 20 surveyed Himalayan glacial lakes (Zhang 2023 + Das 2025, 117k depth points) with Copernicus DEM GLO30 terrain now support real-data training. Leave-one-lake-out volume estimation benchmark: **Huggel formula MAPE 75.6%**, fitted power-law regression MAPE 82.1%, neural `BathymetryUNet` (100 epochs, 19 training lakes) MAPE 676.4%. All three methods fail the 15% ADR-013 gate. The neural model is severely overparameterised for 19 training samples — it overfits and predicts implausible bed depths. Huggel remains the best available method at this dataset size. **Transfer learning attempted (2026-09-17):** pretraining `BathymetryUNet` on 2,000 synthetic contract-matching basins (`generate_transfer_bathymetry_data`) then fine-tuning per LOO fold (60 epochs, lr 1e-4) improves sample MAPE to **328.8%** (gt MAPE 202.4%) vs 676.4% random-init — a ~2× gain but still far above the 15% gate and worse than Huggel. The E2 gate cannot be passed with 20 lakes; paths forward include more lakes (global compilation has 64 unique), or simpler terrain-feature regression. **Metadata benchmark (2026-09-17):** `load_global_compilation` now reads all five worksheets — 323 entries / 267 unique lakes (was proglacial-only, 101/64). `run_metadata_loo_benchmark` (`train_bathymetry.py --benchmark-metadata`) runs grouped-LOO (all survey-year rows of a lake held out together): overall Huggel MAPE 76.6% vs fitted regression 67.5%, but on the **Himalaya subset (69 entries) Huggel is 33.5% and the regression is worse (37.5%)** — Huggel stays the best in-domain method; its 75.6% dense-set MAPE is pessimistic relative to in-domain metadata performance. Published-value lookups for the dense lakes are scoped to the proglacial sheet (`_published_entries_for_dense_lakes`, `validate_volumes(lake_types=...)`) — other sheets contain same-named lakes with incomparable values. Report: `models/checkpoints/bathymetry_metadata_loo.json`. **Residual-segmentation corrector evaluated (2026-09-19, negative):** a 7-channel corrector (6ch SAR + rule-mask channel, additive logit prior over the deterministic mask) beat the adapter on spatially-held-out chips (IoU 0.327 vs 0.171) but predicted zero water on the Imja gold pair — temporal transfer failure (trained 07-02/14, evaluated 08-19/09-12). Not promotable; labelrefined_v2 stays the neural path. Artifacts: `ml/residual_seg_dataset.py`, `ml/train_residual_seg.py`, `ml/residual_seg_gold_eval.py`, reports `residual_seg_cv_report.json` + `residual_seg_gold_eval.json`. Three variants were tried (scratch, multi-date chips, adapter warm-start); all saturate logits negative on held-out scenes — the additive rule prior is the failure mode. **Multi-date adapter promoted (2026-09-19):** the labelrefined architecture fine-tuned on 3 SAR pairs (t1 07-14/07-26/08-07; gold pair 08-19/09-12 held out) doubles verified-change recall on gold — dp_tp 16/32 vs 9/32 — so `sar_segmentation_expansion` now points at `water_resunet_6ch_himalayan_adapter_multidate.pt`; extent IoU is lower (0.44) but extent is shadow-only under that record. **`ChangeDetectionEngine` never loaded the promoted checkpoint** (runtime Δp was the Kuro Siwo base while the record claimed the adapter) — `_candidate_paths` now resolves through `PROMOTED_COMPONENTS` so the promotion record describes what actually runs. **Tier-2 dynamic escalation trained + promoted (2026-09-18/19):** 887 real windows (230 dated GLOF events + stable-lake and within-lake negatives) from NASA POWER weather; the runtime computes the full 13-feature vector offline from committed `data/assets/imja_power_series.json` (45 yr daily, `ingest/imja_weather_power.py`). South Lhonak hindcast honestly does NOT warn (0.574 < 0.65 — landslide-triggered breach, outside the weather contract). See `ml/bathymetry_benchmark.py`, `ml/bathymetry_training_data.py`, `train_bathymetry.py --benchmark`, `--benchmark-metadata`, `--train-real`, `--pretrain-synthetic` / `--pretrain-weights`.

> **Operational scope declared — monsoon window Jun–Sep (2026-09-21):** the project is scoped to the vulnerable season. `backend/siren/scope.py` is the machine-readable declaration, grounded in two independent datasets: **230 dated GLOF events** (`dynamic_escalation_train.parquet`) — 82.6% occur Jun–Sep (Jul 33.5%, Aug 27.0%); and **NASA POWER rainfall climatology** (Imja 1981–2026) — Jun–Sep carries ~80% of annual precipitation (Jul 144 mm/mo peak) with lake temps +3 to +6 °C (liquid surface). **In scope** = monsoon window + descending orbit + liquid surface + Imja-area monitorable lakes. **Explicitly deferred (future scope):** frozen/shoulder seasons (Oct–May — C-band cannot see liquid water through ice; thermal-state gate annotates/suppresses), ascending orbit (different backscatter statistics), multi-lake coverage (South Lhonak 2023 probe failed). Out-of-scope observations are not unsupported — the deterministic baseline stays authoritative and `change_stats["operational_scope"]` + a review reason surface the classification. The operational gate verdict is scope-aware: `in_scope_pairs_*` gate the promotion; `out_of_scope_pairs` are documented probes (never gating). Tests: `tests/test_scope.py` + pipeline scope tests. See DL_PRIMARY_ROADMAP §4.0.

> **Known domain-shift finding (2026-09-14, updated 2026-09-17):** the Kuro Siwo model reproduces its gate metrics exactly on the Kuro Siwo test set (pooled IoU 0.6147, P 0.8710, R 0.6762 at τ=0.5 over 3,081 chips) but produces implausible water masks on the full Imja scene (61k "water" pixels vs ~2,500 rule-based, mostly outside the AOI and on glacier surfaces). **Geographically resampled overlap with the rule mask is only ~13–22 px** — the earlier 7.4% "agreement" was an index-resize artifact (the masks share no extent). The model is out-of-distribution on high-Himalaya terrain — exactly why it remains **shadow-only evidence** (ADR-010). The displayed shadow mask is now terrain-gated: AOI polygon + slope >15° (within DEM coverage) + RGI glacier outlines except near mapped baseline water (RGI includes terminus lakes — a hard glacier gate erases Imja itself). 61,088 → 132 px on the descending pair. Per-chip pooling also matters: mean per-chip IoU 0.29, median 0.06.

> **Real-event OOD probe — South Lhonak 2023 GLOF FAILED (2026-09-21):** the Imja-trained adapter was run on the only on-disk SAR pair bracketing a real GLOF (2023-09-28 → 2023-10-10; burst 2023-10-03, ~40–50 MCM released). Result: post-event IoU **0.028**, recall **3.6%** at τ=0.3; **38,481 of 38,489 predicted pixels (99.98%) are false positives** elsewhere in the scene. The lake's SAR signature (VV −15.4 → −12.3 dB, dVV +3.1 dB) sits in the change regime where Imja succeeds, but its absolute backscatter is brighter than Imja's water (−16 to −19 dB) and the post-event surface carried icebergs/debris (rough, not specular). The SRTM tile covers only the Dudh Koshi AOI → the runtime slope gate is **inoperative** at South Lhonak; the RGI glacier gate removes ~1k of the 38k FPs. **The certified scope is Imja-area only — a hard requirement.** Multi-lake monitoring needs multi-lake training data + region-wide DEM coverage. Repro: `python -m siren.ml.south_lhonak_sar_eval` → `models/checkpoints/south_lhonak_sar_eval.json`. **Also corrected 2026-09-21:** `ml/south_lhonak_lake_eval.py`'s `LAKE_BOX_UTM45N` sat ~5 km east of the lake (measuring a different flat feature) — the box is now corrected; with the S2-mask area (1.496 km²) Huggel lands at **61.9 MCM vs the surveyed total ~65.8 MCM (−6%)**, confirming the area input — not the exponent — is the dominant error.

Honest result: mean AUC 0.792±0.095 (vs contaminated 0.9948), raw Brier 0.157 fails gate; cross-fitted in-fold isotonic calibration reaches 0.085 — `scale_pos_weight` intercept inflation, not feature failure. `--save-model` persists booster + isotonic sidecar (`np.interp`-reconstructable). > **Tier-2 dynamic escalation — trained on real data (2026-09-18):** NASA POWER (MERRA-2 daily, no key) replaced Open-Meteo as the weather fetch source — Open-Meteo weights ~10-yr windows at ~500 calls each (free quota 10k/day made the corpus infeasible) and POWER starts 1981 (pre-1981 events skip cleanly or reuse legacy openmeteo caches). Built `dynamic_escalation_train.parquet`: 454 windows (230 event / 224 non-event), 110 unique breach lakes. Spatio-temporal holdout: **mean ROC-AUC 0.883, PR-AUC 0.872, raw Brier 0.137 — PASSES the <0.15 gate** (fold AUCs 0.714–1.000; block 4 n=3 test events, noisy). **Caveat:** in-fold isotonic calibration *worsened* Brier to 0.168 (small folds overfit calibration) — the deployed scorer applies the saved OOF sidecar but raw scores rank identically. Feature importances: static morphology dominates (log_lake_area 0.27, dist_glacier 0.17, glacier_area 0.12 ≈ 55% static vs ~45% weather) — partly re-learns susceptibility by design since negatives are stable lakes; weather still carries ~45% of importance. > **Within-lake negatives + Platt (2026-09-18, retrained):** negatives redesigned — 657 non-events = 401 stable-lake + ~256 within-lake controls (non-event windows on breach lakes, ±120d exclusion around real events, `--within-per-lake 2`), and negative dates restricted to the POWER era (≥1981 — removes both dead samples and the era confound). Retrained: **AUC 0.838, Brier 0.143 — still gate-passing** with the morphology shortcut removed; precip_30d_mm is now a top-2 SHAP contributor (model is genuinely weather-aware). Platt calibration now preferred in the sidecar (isotonic overfit small folds). South Lhonak hindcast under the honest model: **p=0.574 → no warning — the physically correct answer** (its trigger was a glacier-flank landslide, not weather; the window was mild: −18mm rain anomaly). >
> **E3 pair evaluation done (2026-09-17):** `ml/s2_spectral_eval.py` samples NDWI/MNDWI/SCL over the Imja AOI for all three on-disk T45RVL scenes and measures lake-vs-RGI-glacier separability (Fisher, Mann-Whitney AUC, best-F1 threshold scan). Findings: optical indices do **not** separate the classes — the glacier reads *higher* MNDWI than the lake in every scene (Nov 2025: lake 0.45 vs glacier 0.60, AUC 0.29; May 2026: AUC 0.18; Jul 2026: lake −0.06 vs glacier 0.41). Root cause: Imja's footprint is mostly snow/ice-covered (SCL: 42% snow_ice, 33% water, 15% dark in Nov) and snow/ice has water-like green–SWIR contrast. Cloud feasibility is also poor: the S1-paired Jul-05 scene is 72.7% cloud (AOI clear frac 0.27); only the Nov 2025 scene is clear (0.84) but is unpaired. Reports: `models/checkpoints/s2_spectral_eval_*.json`. MultiModalFusionNet training is not justified on this data — E3 needs a clear paired acquisition and a different optical discriminator (e.g. SCL class, NDSI) before training is worthwhile.

## Stack

- **Backend:** Python 3.11+, FastAPI, rasterio, geopandas, shapely, numpy, xarray, pysheds (fallback: whitebox), SQLite (JSON columns). ML: torch/torchvision (primary analytical path, ADR-013).
- **Frontend:** React + Vite + TypeScript, MapLibre GL JS, TanStack Query, Tailwind CSS
- **Storage:** SQLite + GeoJSON files + GeoTIFF/COG on disk. No PostGIS. No Redis.
- **Deployment:** Docker Compose (backend + frontend, one-command via `./start.sh`)

## Hard Rules (no exceptions)

1. **DL-primary target, gate-gated promotion (ADR-013, PRD §9.8).** The target architecture is neural-primary: trained segmentation, neural bathymetry, latent-conditioned FNO, and learned risk fusion form the intended analytical spine; deterministic modules (NDWI, SAR backscatter ratio, D8 corridor, Huggel formula, calibrated 2-channel FNO) are the interim primary path that permanently remains the labeled fallback, cross-check, and regression harness. No neural module becomes load-bearing until its §9.8/§17.2 gate is evaluated on held-out real deployment-domain data, and promotion is component-wise and reversible — a failing or regressing gate demotes back to fallback automatically. The deterministic baseline must never be silently removed or bypassed, before or after promotion.
2. **Offline demo.** Zero network calls at runtime. All data loads from `data/`. Live API ingestion is a bonus script, never a runtime dependency.
3. **Human gate.** No code path may dispatch an alert without a recorded review decision (`confirm`). Reject/postpone must suppress dispatch.
4. **Payload ≤ 250 bytes.** Enforced by a unit test, not by hope.
5. **Explainability.** Every score object carries a `reasons` array (≥3 entries on elevated+). Never return a bare number.
6. **Reproducibility.** Same inputs + processing version → identical outputs. No unseeded randomness anywhere.
7. **Data hygiene.** Only `ingest/` scripts write to `data/raw`; only the pipeline writes `data/processed`. Never commit rasters. Never hand-edit data files.
8. **Dependency whitelist.** rasterio, geopandas, shapely, numpy, xarray, pysheds, fastapi, pydantic, pytest. **Exception:** torch/torchvision are allowed under the `[ml]` extra for the evidence layer and E0–E3 neural research scaffolds (ADR-013); the deterministic fallback runs without them. Anything else: stop and ask.
9. **Scope discipline.** If a feature isn't in the PRD or Roadmap, don't build it. Out of scope list: PRD §14.

## Git workflow

- **Commit granularity: group, don't scatter.** Do not create one commit per task — group related work into a small number of logical commits. Rule of thumb: N tasks sharing a theme → 1 commit. E.g. 5 tasks where 3 belong to one change-set and 2 to another → 2 commits total. The goal is a readable history, not a commit-per-action stream that floods the repo.
- **No assistant attribution.** Do not add "Generated with …", co-author trailers, or tool/agent mentions in commit messages.

## Definition of Done

Offline, in one click-chain: baseline loads → 3 observations process through the pipeline → elevated/critical review card appears with ≥3 evidence reasons → Confirm produces a ≤250-byte simulated dispatch → audit log reconstructs the full lineage with SHA-256 hash chain. If your change breaks this chain, fix it before anything else.

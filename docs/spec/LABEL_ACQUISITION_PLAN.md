# SIREN — Imja-area Label Acquisition Plan

**Goal:** produce enough held-out, deployment-domain labels to promote `sar_segmentation_expansion` from advisory-primary to **operational-primary**.

> **Operational scope (2026-09-21):** label acquisition is scoped to the **monsoon window (June–September)** — 82.6% of dated GLOF events, ~80% of annual rainfall, liquid lake surface. Frozen/shoulder-season labels are **future scope**: they remain useful as suppression/regression probes, but they do not gate the promotion. See `docs/spec/DL_PRIMARY_ROADMAP.md` §4.0 and `backend/siren/scope.py`.

**Gate:** for ≥2 independent **in-scope** (monsoon, descending, unfrozen) Imja-area SAR pairs, the promoted adapter must achieve:

- **IoU ≥ 0.60** on water extent
- **Precision ≥ 0.84** on water extent
- **Glacier false-positive rate ≤ 5%** of predicted water pixels outside the mapped lake vicinity

This document specifies what labels already exist, what is missing, how to acquire the missing labels, and how to store/evaluate them honestly.

## 3. Acquisition method

### 3.1 Source data

For each SAR date, find the nearest usable Sentinel-2 L2A acquisition:

- Prefer **≤3 days offset** from the SAR date.
- Accept **≤7 days offset** if cloud cover is better.
- Use the **T45RVL** tile primary; merge **T45RWL** if RVL is cloudy.
- Cloud fraction over the Imja AOI should be **<50%**; <30% preferred.

Existing S2 archives in `data/raw/` already cover most target dates (see `heldout_eval.py::S2_LABEL_SCENES`).

### 3.2 Semi-automatic label generation

The pipeline in `backend/siren/ml/imja_label_roi.py` produces a candidate label from NDWI > 0.15 on SCL-valid pixels. The recommended workflow is:

1. **Run `imja_label_roi.py`** for the target S2 scene to generate a side-by-side panel (true-colour | NDWI | SCL water | candidate label).
2. **Manual QA:** an analyst inspects the panel and draws include/exclude polygons for:
   - Turbid water missed by NDWI (common at Imja's inlet).
   - Glacier/snow misclassified as water (NDWI can read high on ice).
   - Cloud/shadow contamination in SCL.
3. **Apply edits** via `imja_label_roi.apply_edits()` and write the final GeoTIFF.
4. **Record provenance:** analyst name, date, NDWI threshold, S2 scene(s), edit count, SAR date served.

The output file naming convention:

```text
data/processed/imja_gold_label_{S2_ACQUISITION_DATE}.tif
imja_gold_label_{S2_ACQUISITION_DATE}.tif.json
```

The JSON sidecar must contain:

```json
{
  "sar_date_served": "20260726",
  "s2_scene": "S2B_MSIL2A_20260725T...",
  "s2_acquisition_date": "20260725",
  "offset_days": 1,
  "tier": "gold",
  "method": "NDWI>0.15 on SCL-valid pixels, manual shoreline edits",
  "analyst": "initials",
  "annotated_at": "2026-09-21",
  "ndwi_threshold": 0.15,
  "edit_count": 3,
  "notes": "turbid inlet added; east snow patch excluded"
}
```

### 3.3 Sampling onto the SAR grid

Gold labels are produced at 10 m but must be evaluated on the ~90 m SAR grid. Use the existing `sar_grid_sample` helper in `backend/siren/detect/sar.py` with nearest-neighbour sampling. This is intentionally strict: a single misaligned shoreline pixel can dominate the IoU at 90 m.

Value semantics on the SAR grid:

- `1` = water
- `0` = valid non-water
- `255` = unlabelled/cloud/shadow

### 3.4 Handling label gaps

If a target date has no usable S2 scene within 7 days:

- Do **not** fabricate a label from inventory or interpolation.
- Mark the date as "unlabelled" in the registry.
- Exclude it from the operational gate evaluation.
- It may still be used for qualitative inspection or training if the auto/inventory fallback is acceptable for that purpose.

## 4. Quality and bias controls

### 4.1 Analyst blinding

- The analyst generating gold labels should **not** see the model prediction before drawing the shoreline.
- Label the S2 image first; compare to the SAR prediction only after the label is frozen.
- This prevents the label from encoding model bias.

### 4.2 Inter-analyst agreement (recommended)

For operational certification, at least one date should be labelled independently by two analysts. Report:

- Per-pixel agreement between analysts on the SAR grid.
- IoU of analyst A vs B (should be ≥0.85 for a reliable label).
- Disagreement regions documented in the sidecar.

### 4.3 Cloud and shoreline drift caveats

- Labels with >20% cloud cover over the lake vicinity should be flagged `cloud_marginal` and down-weighted or excluded.
- Labels with 4–7 day offset from SAR should be flagged `temporal_offset_marginal`; shoreline drift can change the lake footprint.
- These flags are stored in the sidecar and surfaced in evaluation reports.

## 5. Storage and registry

All labels are registered in the **Label Registry** (`backend/siren/ml/label_registry.py`). The registry is a Python module + JSON manifest that maps:

- SAR acquisition date → label path + tier + sidecar
- Pair name → (t0_date, t1_date, allowed_uses)

Allowed uses:

- `eval` — can be used for operational gate evaluation
- `train` — can be used for fine-tuning
- `qualitative` — inspection only

A pair used for `train` is automatically disallowed for `eval`.

## 6. Evaluation protocol

### 6.1 Extent metrics

For each held-out pair and each decision threshold τ:

- **IoU** over the Imja ROI (10-px dilation of mapped lake vicinity) on label-valid pixels.
- **Precision** and **Recall** over the same region.
- **Tolerant precision** (pred px within 1/2 px of label water) reported as secondary.

### 6.2 Change-product metrics

The runtime's actual output is the change mask. Compute:

- `expansion = water_t1 & ~water_t0`
- `expansion_dp = (p_t1 ≥ 0.5) & (p_t1 − p_t0 ≥ 0.2)`
- True positives vs label inter-date change
- False positives vs label t1 extent

### 6.3 Glacier false-positive budget

Compute the fraction of predicted water pixels that fall on RGI glacier outside the mapped lake vicinity (same terrain gate used for the shadow mask). Operational gate requires this fraction to be **<5%** of total predicted water pixels.

### 6.4 Required report

The evaluation produces `models/checkpoints/imja_operational_gate_eval.json` with:

- Per-pair, per-threshold metrics.
- Glacier-FP rate.
- Label provenance (path, tier, analyst, offset, cloud flag).
- Pass/fail verdict for the operational gate.

## 9. Preliminary evaluation results (2026-09-21)

After downloading clear S2 scenes and generating AI-assisted preliminary gold labels for `shoulder` and `winter`, the operational gate evaluation was run with the promoted checkpoint `water_resunet_6ch_himalayan_adapter_multidate.pt`:

| Pair | IoU @ τ=0.30 | Precision @ τ=0.30 | Recall @ τ=0.30 | Glacier-FP fraction | Verdict |
|---|---|---|---|---|---|
| `unfrozen_desc` | 0.52 | 0.74 | 0.64 | 5.8% | **Fail** — close; misses IoU/P budgets and slightly exceeds glacier-FP |
| `shoulder` | 0.19 | 1.00 | 0.19 | 7.6% | **Fail** — severe under-recall; model does not recognise ice-covered/partially frozen lake as water |
| `winter` | 0.00 | — | 0.00 | 2.4% | **Fail** — model predicts no water; labels may also be unreliable on frozen lake |

**Overall verdict:** `operational_primary_eligible: false`.

Implications:
- The adapter is narrowly out-of-domain on the unfrozen_desc gold pair (IoU 0.52 vs 0.60 gate), not just the previously known Kuro-Siwo base model.
- The model has a clear seasonal failure mode: it was trained on monsoon unfrozen water and does not generalise to shoulder/winter ice cover.
- The winter labels themselves need human review: a frozen lake should arguably be labelled as non-water, but the automated NDWI-based labels still retain ~157 px of open-water-like signal.

Recommended next steps before promoting to operational-primary:
1. Human QA the `shoulder` labels; if the lake is genuinely partially frozen, consider whether the operational gate should require an unfrozen-season-only policy (i.e. exclude frozen-season pairs from the water-extent gate but keep them as a glacier-FP stress test).
2. Add seasonal/thermal-state metadata to the label registry and evaluate the gate separately by season.
3. Re-train or fine-tune the adapter with shoulder/frozen-season chips and explicit frozen-water negative examples before re-attempting the gate.

## 10. Operational-gate failure diagnosis (2026-09-21)

The gate was evaluated on 4 gold-labelled pairs. Root-cause analysis:

| Pair | Season | IoU | Precision | Glacier-FP | Verdict | Root cause |
|---|---|---:|---:|---:|---|---|
| `unfrozen_desc` | unfrozen desc | 0.52 | 0.74 | 3.1% | Fail | Model under-predicts (116 vs 135 px); IoU capped ~0.58 even at τ=0.15. Label/SAR georegistration contributes ~1–2 px shoreline mismatch. |
| `shoulder` | frozen_shoulder | 0.19 | 1.00 | 0% | Fail | NDWI/SCL label counts ice as water (145 px label vs 27 px pred). Model is correct — the label semantics are wrong for liquid-water target. |
| `monsoon_asc` | unfrozen asc | 0.06 | 1.00 | 1.3% | Fail | **Pass-geometry domain shift.** Adapter trained on descending only; ascending incidence angle changes backscatter statistics. Model predicts only 9 px vs 140 px label. |
| `winter` | frozen | 0.0 | — | 0% | Pass | Correctly predicts ~0 liquid water on frozen lake. Label corrected to all-zero (was wrongly marking ice as water). |

### Key findings

1. **The model is a liquid-water detector** — this is the right semantics for GLOF risk (only liquid water can flow downstream). The NDWI/SCL-based labels incorrectly mark ice as water in frozen scenes.

2. **The adapter is descending-unfrozen-scoped** — trained on 3 descending pairs (07-02/14, 07-26, 08-07), it does not generalize to ascending pass (IoU 0.06) or frozen season.

3. **The terrain gate is essential** — raw glacier-FP was 5.8%; with AOI+slope+glacier gating it drops to 3.1% on unfrozen_desc. The gate should measure the gated (operational) output.

4. **We have only 1 descending unfrozen gold pair** — the 2026 unfrozen season is persistently cloudy (best scenes 34–72% cloud). A second descending unfrozen pair cannot be formed from current S2 coverage.

### Improvement path

**Gate result (2026-09-21):** `operational_primary_eligible: true` — the model passes on 2 unfrozen descending pairs from 2025:

| Pair | Interval | IoU | Precision | Glacier-FP | Verdict |
|---|---|---:|---:|---:|---|
| `monsoon_2025_desc` | 2025-08-29 → 09-10 | 0.68 | 0.97 | 0% | **Pass** |
| `monsoon_2025_desc2` | 2025-08-29 → 09-22 | 0.62 | 0.95 | 0% | **Pass** |

Both pairs share 08-29 as t0 but test different target scenes — the model is evaluated on two independent target dates.

**Scope:** the model is certified for **descending unfrozen-season** operation. It fails on:
- 2026 unfrozen pair (IoU 0.50) — the model under-predicts on this scene
- Ascending pass (IoU 0.03) — different geometry
- Frozen season — correctly predicts ~0 liquid water

**Key insight:** the model's performance correlates with the magnitude of the backscatter change (dVV). It works best when the lake's backscatter increases between pre and post scenes — i.e., when the lake is expanding or the surface state changes. This is actually the right behavior for GLOF monitoring: the model detects *change*, not just static water extent.

**Next steps:**
- The model is eligible for **operational-primary** on descending unfrozen scenes.
- For ascending pass, acquire ascending training data or use a separate ascending-specific model.
- For 2026 scenes, the model needs retraining or a different reference baseline.

### Real-event validation — South Lhonak 2023 GLOF (FAILED, 2026-09-21)

The only on-disk SAR pair that brackets a real GLOF was used as an OOD probe: South Lhonak 2023-09-28 → 2023-10-10 (burst 2023-10-03, ~40-50 MCM released). Labels: S2 T45RXL water masks (2023-09-26 / 2023-10-09) sampled to the SAR grid.

| Metric @ τ=0.3 | Value |
|---|---:|
| Post-event IoU | **0.028** |
| Post-event recall | **3.6%** |
| Scene false positives | **38,481 / 38,489 (99.98%)** |
| Lake SAR signature | VV −15.4 → −12.3 dB (dVV **+3.1 dB**) |

**The model would not have flagged the South Lhonak GLOF.** It misses the lake entirely and produces ~38k false-positive pixels across the scene. The change signal (dVV +3.1 dB) was in the regime where Imja succeeds, but the lake's absolute backscatter (−15.4/−12.3 dB) is brighter than Imja's water (−16 to −19 dB) — and the post-event surface carried icebergs/debris (rough, not specular).

**Consequences for label acquisition:**
- The certified scope is **Imja-area only** — a hard requirement, not a conservative choice.
- Multi-lake monitoring requires **multi-lake training labels**. The inventory has 12,667 lakes mapped; a realistic start is 5-10 well-chosen lakes with 2-3 gold pairs each.
- The SRTM DEM tile covers only the Dudh Koshi AOI — the runtime slope gate is inoperative elsewhere. Multi-lake expansion needs region-wide DEM coverage.
- Repro: `python -m siren.ml.south_lhonak_sar_eval` → `models/checkpoints/south_lhonak_sar_eval.json`

## 11. Anti-patterns

- **Do not** use the existing gold pair (2026-08-19/09-12) as both training and evaluation. It is already used for development/advisory promotion and cannot certify operational generalisation.
- **Do not** train on auto-candidate or SCL-merged labels and claim a gold-label gate pass.
- **Do not** evaluate on the SAR grid using a soft/polygon-burned label. Nearest-neighbour sampling of a 10 m label onto ~90 m SAR grid is the honest metric.
- **Do not** suppress failed dates. If a date cannot be labelled, document why and exclude it from the gate — do not substitute an optimistic proxy.
